# 09 Agent Loop、计划、验证与 Subagent

目标：把 Hermes agent loop 建成会话内唯一决策循环，使它能够自主计划、执行、验证、纠错和有证据地收口。

模块状态：⬜ 未开始

前置依赖：08 完整工具、skill 和策略运行时。

状态图例：✅ 已完成；🟨 待确认或已有基础但未验收；⬜ 未开始。

## 09.1 主循环适配

- ⬜ 接入模型决策、工具调用、结果回灌、继续决策和终止判断。
- ⬜ chatsvc 不解析模型文本猜测状态，不保留第二套 loop。
- ⬜ 每轮保持合法消息交替，不注入伪造用户消息推进循环。

## 09.2 Goal 和 Plan

- ⬜ 从用户输入识别目标、约束、完成标准和禁止事项。
- ⬜ 复杂任务生成可更新计划，简单任务允许直接回答。
- ⬜ plan.updated 反映真实状态变化，不把展示计划当作执行引擎。

## 09.3 Outcome 与验证

- ⬜ 区分工具正常退出、业务结果满足、证据充分和目标完成。
- ⬜ 对关键结论执行独立验证或查询实际状态。
- ⬜ 记录证据引用、置信来源、未解决项和交付范围。

## 09.4 纠错和终止

- ⬜ 参数错误、权限拒绝和工具失败以结构化结果回灌。
- ⬜ 实现重试总预算、无进展检测、重复动作检测和替代方案选择。
- ⬜ 达到预算、不可恢复错误或用户取消时产生明确终态。

## 09.5 Subagent

- ⬜ 支持独立子任务委派、并行执行、结果收集和取消。
- ⬜ 限制递归深度、并发、时间、输出和资源冲突。
- ⬜ 子任务完成不等于父目标完成，冲突结果触发补查或明确不确定性。

## 09.6 行为验收

- ⬜ 简单问答、工具纠错、验证失败、并行子任务和预算耗尽场景通过。
- ⬜ 使用确定性模型/工具桩验证控制不变量，再用真实运维任务评估完成率。
- ⬜ H1 最小闭环和主循环验收完成后，将模块状态更新为 ✅。
