# 10 用户交互、Steer、取消与审批

目标：让用户能够在运行中补充、纠正、回答、批准、拒绝和取消，并由 Runtime 确定性等待与恢复。

模块状态：⬜ 未开始

前置依赖：09 可运行的 Agent Loop。

状态图例：✅ 已完成；🟨 待确认或已有基础但未验收；⬜ 未开始。

## 10.1 输入分类和关联

- ⬜ 区分新目标、目标补充、turn.steer、澄清答案、审批结果和取消。
- ⬜ 每次输入关联明确 interaction/run/item 版本，过期输入不得误触发当前动作。
- ⬜ 重复答案和重复审批幂等处理。

## 10.2 澄清

- ⬜ clarification.requested 包含问题、选项、原因、阻塞范围和超时。
- ⬜ Runtime 挂起依赖分支，而不是要求模型“自行等待”。
- ⬜ 用户回答后恢复正确 run；可并行的不依赖分支按计划继续。

## 10.3 审批

- ⬜ approval.requested 绑定具体工具、参数摘要、风险、作用域和有效期。
- ⬜ 批准只对请求版本和授权范围有效，参数变化必须重新审批。
- ⬜ 拒绝、过期和撤销均产生结构化 outcome，模型不能自行授权。

## 10.4 Steer 和取消

- ⬜ steer 更新后续决策，不篡改已完成历史。
- ⬜ 区分 cancel requested、tool cancellation acknowledged 和 unknown result。
- ⬜ 取消向 tool/subagent 传播，有副作用操作无法确认时进入 unknown。

## 10.5 断连和等待策略

- ⬜ 定义前端断连、host 重连、等待超时和后台继续策略。
- ⬜ waiting 状态可持久化、可查询、可恢复，不依赖活跃模型调用。
- ⬜ 超时后按策略取消、阻塞或交付部分结果。

## 10.6 模块出口

- ⬜ H3 的 steer、澄清、审批、取消和等待 E2E 全部通过。
- ⬜ 过期、重复、乱序和参数变化场景 fail closed 后，将状态更新为 ✅。
