# 11 事件投影、Artifact 展示与审计

目标：把 Harness 内部事实转换成用户可理解、可追溯且不泄露敏感信息的客户端事件和审计记录。

模块状态：🟨 已有基础字段脱敏

前置依赖：10 完整交互与控制语义。

状态图例：✅ 已完成；🟨 待确认或已有基础但未验收；⬜ 未开始。

## 11.1 可见性策略

- ✅ 已有 system prompt、chain of thought、authorization、secret 等字段递归脱敏基础。
- ⬜ 按事件类型、工具、tenant 和 profile 决定可见、摘要、artifact-only 或永不透传。
- ⬜ 系统提示、原始思考、密钥和内部配置在后端出口前过滤，不能只依赖前端折叠。

## 11.2 事件投影

- ⬜ 投影 assistant、plan、tool、subagent、interaction、artifact、warning、error 和终态。
- ⬜ 每个可见事件关联 session、run、item/invocation 或 artifact。
- ⬜ 合并高频 delta，保留最终正文和缺口标记。

## 11.3 Artifact 可见引用

- ⬜ 输出名称、类型、大小、摘要、来源和安全下载/查看引用。
- ⬜ 原始网页、完整命令输出和大型资料默认隐藏，仅按授权读取。
- ⬜ artifact 删除、过期或不可访问时前端得到明确状态。

## 11.4 审计事实

- ⬜ 记录协议身份、actor、工具 intent、审批、epoch、结果和证据引用。
- ⬜ 审计记录不可包含密钥和隐藏思维链。
- ⬜ 定义保留期、访问控制、导出和诊断快照。

## 11.5 一致性测试

- ⬜ 实时流、最终事件、持久记录和重新进入后的历史语义一致。
- ⬜ 敏感数据从工具结果到协议出口全链路不会泄漏。
- ⬜ 迟到事件只能记录事实，不能重新激活已结束 run。

## 11.6 模块出口

- ⬜ 客户端可见事件矩阵和审计矩阵完成安全评审。
- ⬜ 投影、脱敏、一致性和 artifact 访问测试通过后，将状态更新为 ✅。
